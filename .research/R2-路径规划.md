# R2 媒体存储路径规划

> 适用对象：`somarkit-assets` 存储桶 · 本站所有用户上传的图片素材
> 相关代码：`src/lib/media.js`、`wrangler.toml` 的 `[[r2_buckets]]`
> 最后更新：2026-11-19

---

## 1. 基础设施

| 项目 | 值 |
|---|---|
| 存储桶 | `somarkit-assets` |
| Worker 绑定 | `MEDIA`（`wrangler.toml` → `[[r2_buckets]]`） |
| 公网域名 | `https://images.somarkit.com`（环境变量 `MEDIA_BASE_URL`） |
| 上传入口 | `POST /admin/api/upload`（需后台登录） |
| 缓存策略 | `public, max-age=31536000, immutable` |

> **为什么用独立桶**：与 `4k-videos` 等其他项目的素材完全隔离，配额、生命周期规则、
> 权限都能单独管理，误删风险低。

## 2. 目录结构

所有对象键遵循 **`<类别>/<slug>/<hash>-<时间戳>.<扩展名>`** 的格式：

```
somarkit-assets/
├── logos/
│   └── chatgpt/
│       ├── 3f2a9c1b-m3k8p1.png
│       └── 7d4e0a2f-m3k9x7.webp
│   └── cursor-composer/
│       └── a1b2c3d4-m3ka2v.svg
├── reviews/
│   └── chatgpt/
│       ├── 9e8f7a6b-m3kb5n.jpg     # 评测正文里的插图
│       └── 2c3d4e5f-m3kb8q.png
└── categories/
    └── ai-chat/
        └── 5a6b7c8d-m3kc1r.svg
```

### 2.1 类别目录

| 目录 | 用途 | 单文件上限 | 使用位置 |
|---|---|---|---|
| `logos/` | 工具 Logo | **512 KB** | 工具编辑页「Logo」字段 |
| `reviews/` | 评测正文插图 | **2 MB** | Markdown 编辑器 |
| `categories/` | 分类图标（预留） | 512 KB | 暂未启用 |

### 2.2 slug 规则

- 取自工具 / 分类的 `slug` 字段，经 `safeSegment()` 处理：
  - 小写化、去除引号
  - 非 `[a-z0-9中文]` 字符转 `-`，删除首尾 `-`
  - 最长 60 字符
- **新增工具时 slug 可能还是空的**，此时回退顺序为：`slug` 输入框 → 已有 slug →
  工具名称 → `'review'`。保存工具后产生的对象仍然归在该工具名下。

### 2.3 文件名规则

```
<hash>-<timestamp>.<ext>
 └─ SHA-256 前 4 字节（8 位十六进制），内容寻址，便于识别重复上传
             └─ Date.now().toString(36)，保证同一内容重复上传也不覆盖
```

示例：`3f2a9c1b-m3k8p1.png`

**为什么不用原始文件名**：原始名称可能含中文、空格、超长字符，直接入 key 会导致
URL 编码混乱；用 hash + 时间戳既安全又不会冲突。原始文件名保存在 `<img>` 的
`alt` 文本里（Markdown 插入时自动填写）。

## 3. 上传流程

```
浏览器选择文件
   ↓
POST /admin/api/upload  (multipart: file, kind, slug)
   ↓
① 会话校验（必须已登录后台）
② MIME 白名单：png / jpeg / webp / gif / svg / avif
③ 大小校验：logo ≤ 512KB，review ≤ 2MB
④ 计算 hash、生成 key
⑤ MEDIA.put(key, 内容, {contentType, cacheControl, customMetadata})
⑥ 写审计日志 media.upload
   ↓
返回 { ok: true, key, url, bytes }
   ↓
前端把 url 写入 logo_url 字段 / Markdown 光标位置
```

### 安全措施

| 风险 | 处理 |
|---|---|
| 上传可执行文件 | 只接受 6 种图片 MIME，按 MIME 决定扩展名 |
| 超大文件占满配额 | 按类别限制体积，服务端校验（不依赖前端） |
| 未授权上传 | 路由位于后台鉴权之后，必须登录 |
| 路径穿越 | `safeSegment()` 剥离 `..`、`/`、`\` 等字符 |
| SVG 携带脚本 | 由浏览器侧 `<img>` 渲染，不执行内联脚本；如需更严格可在 R2 域名加 CSP |

## 4. 访问与缓存

- 公共 URL：`https://images.somarkit.com/<key>`
- 对象被标记为 `immutable` + 1 年缓存，因为 **key 含 hash，内容永不修改**
  —— 换图必然产生新 key，不存在缓存不一致问题
- 旧文件不会自动删除（见下节）

---

## 5. 生命周期与清理

当前**没有自动清理**，原因：工具编辑时可随时更换 Logo，旧文件删除后
若用户点「取消」会导致原图丢失。

建议的运维策略：

| 场景 | 做法 |
|---|---|
| 定期核对孤儿文件 | 用 `wrangler r2 object list somarkit-assets --prefix logos/` 导出清单，与 `SELECT logo_url FROM tools` 比对 |
| 删除工具 | 当前会保留其 R2 文件（`DELETE FROM tools` 不联动 R2）。如需级联删除，在 `deleteTool` 后调用 `deleteMedia(env, tool.logo_url)` |
| 成本控制 | 单张 Logo < 512KB、评测图 < 2MB，1 万张约 5GB，R2 免费额度 10GB / 月 |

`src/lib/media.js` 已提供 `deleteMedia(env, url)`，它只会删除
`MEDIA_BASE_URL` 前缀下的对象，外部图床链接不会被误删。

## 6. 扩展约定

新增一类素材时，只需在 `src/lib/media.js` 的 `UPLOAD_KINDS` 里加一项：

```js
screenshots: { dir: 'screenshots', maxBytes: 4 * 1024 * 1024 },
```

同时在本文档 §2.1 补充说明。**不要**在模板里硬编码目录名。

## 7. 相关命令

```bash
# 查看桶内容（前 20 个）
npx wrangler r2 object list somarkit-assets --prefix logos/ --max-keys 20

# 查看单个对象
npx wrangler r2 object get somarkit-assets/logos/chatgpt/xxx.png --file out.png

# 删除单个对象
npx wrangler r2 object delete somarkit-assets/logos/chatgpt/xxx.png

# 统计各目录对象数
npx wrangler r2 object list somarkit-assets --prefix logos/ | wc -l
```
